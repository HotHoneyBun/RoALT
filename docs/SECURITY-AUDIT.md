# RoALT security audit — initial findings (phase 1, no code modified)

- Source: `inspectsoftware/RoALT` `main`, downloaded 2026-11-07 as a zip (SHA-256 `1620115B6B622169A82DE47F1D69AA7A45D26650185A57B73555EF46925E3293`), extracted to `src-original/RoALT-main`. All paths below are relative to that folder.
- Version in source: 1.0.2 (`src-tauri/tauri.conf.json:4`).
- Method: manual review of every Rust module that touches credentials, network, processes, files, registry and the WebView, plus the Tauri config/capabilities, installer script, build script and CI workflows. Dependency advisories were checked against OSV.dev (the RustSec + GitHub Advisory data that cargo-audit / npm audit use) for all 598 crates and 131 npm packages in the lockfiles.
- Not done yet: `cargo test`, native `cargo audit` / `npm audit`, and the build. None of the toolchains are installed on this PC. The original installer was **not** run.
- Triage sample: `RoALT-Setup-1.0.2.exe`, SHA-256 `948f65dada60b4404ed66bb7c1626fdd562e3ebacde7740754eac0607c1c06a9`. The public page shows 8 of its 34 signatures and no process tree, network or registry details.

## A. Confirmed issues (proposed for fixing)

|---|---|---|---|---|
| A1 | Medium (privacy) | `src-tauri/src/model.rs:505`, `src-tauri/src/online.rs:15,45`, `src/data.ts:95` | The "online counter" is **on by default**. Every 2 minutes, including in the background, it POSTs a per-launch UUID and the number of running Roblox clients to `roalt-online.roalt-counterlive.workers.dev`, a third-party Cloudflare Worker, which also sees the user's IP. It is disclosed and has a switch, but it is opt-out. | Default to `false` (opt-in). Keep the feature and the switch. |
| A2 | Medium (privacy) | `src-tauri/src/model.rs:504`, `src-tauri/src/rpc.rs:94-125` | Discord Rich Presence is **on by default**. It publishes "Playing <game>" and "Running N alts" on the user's public Discord profile. This is local IPC only, nothing goes from RoALT to the network, but it exposes alt usage to friends. | Default to `false` (opt-in). |
| A3 | Medium (CI supply chain) | `.github/workflows/winget.yml:19` | A third-party action pinned to a moving branch (`vedantmgoyal9/winget-releaser@main`) receives the `WINGET_TOKEN` secret. The workflow has no `permissions:` block, so it gets the repository-default `GITHUB_TOKEN` scope. | Pin to a full commit SHA. Add `permissions: {}`. |
| A4 | Low–Medium (CI supply chain) | `.github/workflows/release.yml:32,42,45,53,60,101,115`, `ci.yml:17,18,25,28` | Actions are pinned to mutable tags (`@v7`, `@v2`, `@stable`). | A5 | Low (defense in depth) | `src-tauri/src/roblox_api/mod.rs:619-629, 714-725` | `request()` attaches `Cookie: .ROBLOSECURITY` to whatever URL it is given. There is no host check. | A6 | Low | `src-tauri/src/main.rs:288-302` | The data-folder ACL hardening (`icacls /inheritance:r /grant:r %USERNAME%:F`) relies on the `%USERNAME%` environment variable. I found no cookies, tickets, webhook URLs or passwords in log calls (cookie errors never quote bodies, and header values are marked sensitive). ## B. Suspicious-looking but legitimate (keep; explained)

| # | Behavior / Triage signature | File:line | Assessment |
|---|---|---|---|
| B1 | **Root certificate installed (ISRG Root X1)**, MITRE T1553.004 | No certificate-store API anywhere in the code (no `CertAddCertificate*`, `CertOpenStore`, `certutil`). TLS goes through `reqwest` + `rustls-platform-verifier` (`Cargo.lock:3751`), which calls Windows' chain engine. `authenticode.rs:58-66` checks revocation online. | **Not done by RoALT.** On a fresh VM, Windows' *automatic root certificate update* (CAPI2) downloads a missing trusted root into `AuthRoot` the first time any process validates a chain that ends in it. RoALT validates chains at startup (self-update check `main.rs:454`, client-version check, news, counter), and WebView2 does the same. This is normal Windows behavior. Do not disable it. |
| B2 | **Checks whether UAC is enabled** | `installer/RoALT.iss:29` (`PrivilegesRequired=lowest`). App: `src-tauri/src/instances/qos.rs:47-90` | Inno Setup checks the token's elevation even for per-user installs. The app's only elevation is the optional bandwidth limit: UAC `runas` of built-in PowerShell `New-NetQosPolicy` with only a range-checked integer, ActiveStore only (gone at reboot), and only on an **Apply** click. No silent elevation. |
| B3 | **Active Setup persistence (HKLM)** | No registry writes in RoALT (no `RegSetValue*`, `RegCreateKey*`, Run keys, tasks or services). | B5 | Process handle manipulation | `instances/multi.rs:1-9, 380-470` | Multi-instance: holds the `ROBLOX_singletonEvent` name. On the user's confirmation, it closes that handle inside Roblox with `DuplicateHandle(DUPLICATE_CLOSE_SOURCE)` (`PROCESS_DUP_HANDLE` only). No memory writes, no remote threads, no DLL injection. |
| B6 | Global low-level **mouse** hook, synthetic input | `instances/resize.rs:357-377` (WH_MOUSE_LL, app lifetime), `instances/afk.rs` (`SendInput`, anti-AFK) | Free resizing and anti-AFK. ## C. Verified-good controls (no change needed)

- **Credential flow.** `.ROBLOSECURITY` is sent only by `roblox_api::request` to constant `*.roblox.com` URLs: no cookie jar, `Policy::none()` redirects, the header is marked sensitive, and rotated cookies are shape-checked (`roblox_api/mod.rs:79-88, 800-827`). WebView sessions inject the cookie only on `.roblox.com` (`webview.rs:376-385`). No other code path transmits a cookie.
- **Encryption at rest.** SQLCipher whole-DB encryption with a random 256-bit key wrapped by DPAPI with app entropy (`storage/cipher.rs`). Every secret is additionally sealed with AES-256-GCM: random 96-bit nonce, row-bound AAD (`roalt.cookie:<user_id>`) (`vault/master.rs:97-115`, `vault/mod.rs:51`). Master mode uses Argon2id 64 MiB / t=3 / p=4 with a random salt. The recovery code uses Argon2id 256 MiB and is never stored. Keys are zeroized.
- **IPC.** Every app command goes through the `main_only` guard (`main.rs:266-275`). The capability is granted to `main` only and gives plugins narrowly (`capabilities/main.json`). There is no fs or shell plugin, and the opener allows only listed URLs. The main window can't navigate off `tauri.localhost` (`main.rs:278-284`).
- **CSP.** `default-src 'self'`; no `unsafe-eval` and no remote scripts; `connect-src` is IPC only; `frame-ancestors 'none'`. No `innerHTML` or `eval` anywhere in the frontend.
- **Roblox windows.** No capability, devtools off in release, autofill/password save/context menu off, a navigation allowlist enforced twice (`webview.rs:604-626`). Google/Apple cookies and `.ROBLOSECURITY` are wiped on open and close. Profiles left open by a crash are deleted. `WEBVIEW2_*` override environment variables are removed at start (`webview.rs:302-310`).
- **TLS.** No `danger_accept_invalid_*`, no custom roots, and verification uses the platform verifier.
- **Diagnostics export** redacts cookies, tickets, webhooks, auth headers, user folders, IPs, job ids and URL queries (`diagnostics.rs:20-30`).
- **Installer.** Per-user, no admin. It ships one file (`RoALT.exe`) with no scripts or bundled software. It only *opens* Microsoft's WebView2 link when asked and downloads nothing. Uninstall asks before deleting user data and defaults to keeping it. It never touches Defender or SmartScreen.
- **Dependencies (OSV).** npm: 0 advisories. Rust: 6 hits, none in the Windows binary: `glib 0.18.5` (RUSTSEC-2024-0429) and `zbus_names`/`zvariant`/`zvariant_derive` (unmaintained) are Linux-only GTK/D-Bus dependencies of Tauri, and `proc-macro-error` (unmaintained) is build-time only. Upgrading them means upgrading Tauri upstream, so no action is proposed.

## D. Unresolved

| # | Item | Why unresolved / what would settle it |
|---|---|---|
| U1 | Triage's "Active Setup", "Downloads MZ/PE file", "Executes dropped EXE", "Loads dropped DLL" | The public report shows no process tree. The installer itself drops and runs its temporary `is-*.tmp` setup helper (normal for Inno Setup). RoALT downloads executables only on a user click. Edge/WebView2 updaters in the VM are the likely source of the Active Setup and PE-download signatures. Confirming this needs Triage's full behavioral log (processes, files, registry), which requires a Triage account, or a monitored run of a *source-built* installer in a VM. |
| U2 | Is the released 1.0.2 binary built from this source? | Release binaries are not Authenticode-signed and builds aren't reproducible. Building from source and using that build (the plan here) sidesteps the question. |
| U3 | Popups (`window.open`) in Roblox/Google sign-in windows | There is no `NewWindowRequested` handler, so a popup gets WebView2's default window, outside `on_navigation`. It has no IPC and only shares the profile. Needs a runtime test before changing anything. |
| U4 | Deployed online-counter worker | Only the in-repo source (`server/online-counter/worker.js`) can be reviewed. It stores nothing on disk, but the deployed version can't be verified. Moot if A1 is applied and the user leaves the counter off. |
| U5 | Native `cargo test`, `cargo audit`, `npm audit`, clippy | Need Rust, Node, VS Build Tools (C++), Strawberry Perl (SQLCipher's OpenSSL) and Inno Setup 6.6+. |

## E. Decisions needed before phase 2

1. **Approve fixes A1–A8.** All are small and preserve every feature. A1 and A2 change only defaults for settings that were never saved. For existing users, a stored `onlineCount: true` stays as is unless a one-time migration is added.
2. **Self-update in a self-built fork.** `self_update` is on by default (`model.rs:503`). It checks upstream GitHub every 6 hours, and an **Install** click would replace the hardened build with upstream's release (signed by upstream's key). Options: keep it as is, default it to off, or disable it in this build.
3. **Build environment.** Windows Sandbox needs Windows Pro (this PC runs Home). Options: (a) a GitHub Actions run on your own fork, which is isolated, matches the upstream release pipeline and produces the installer and its SHA-256; (b) installing the toolchains on this PC (several GB, changes the system); (c) a Hyper-V or VirtualBox VM you provide.
